# JoyNodeWeb
Webブラウザ上でゲームコントローラの操作をキャプチャし、`sensor_msgs::msg::Joy`としてPublishします。

ROS2 Humbleでのみ動作確認を行っています。

# 依存関係のインストール
```bash
sudo apt install python3-pip python3-fastapi python3-uvicorn
```

# リポジトリのビルド
```bash
# ros2の任意のワークスペース内にこのリポジトリをクローンしてビルドします。
git clone https://github.com/KinkiKnights/joy_node_web.git
cd ..
colcon build

# ビルド後にワークスペースを再読み込み
source ./install/local_setup.bash
```

# 起動

ROSノード（WebSocketエンドポイント `/joys`）と、ブラウザクライアントの配信（`/joy`）は分離されています。
それぞれ単体で起動できますが、**オプションを指定しなければノードが配信も兼ねる**ため、従来通りの使い方が変わることはありません。

## 1. ノード + クライアント配信（既定）
```bash
ros2 run joy_node_web joy_node
```
起動後、[http://ドメイン or IP:8700/joy](http://127.0.0.1:8700/joy)へアクセスするとコントローラの情報が`/joy`でPublishされます。
クライアントとWebSocketが同一オリジンになるため、接続先の設定は不要です。

ノードのオプション:

| オプション | 既定値 | 説明 |
|---|---|---|
| `--host` | `0.0.0.0` | バインドアドレス |
| `--port` | `8700` | `/joys`（および配信する場合の`/joy`）のポート |
| `--no-client` | - | クライアント配信を行わない（ノード単体） |

ROS引数と併用できます: `ros2 run joy_node_web joy_node --no-client --ros-args -r __ns:=/five`

## 2. ノード単体
```bash
ros2 run joy_node_web joy_node --no-client
```
`/joys`のみを提供します（`/joy`は404）。クライアントは別ホスト・別ポートから配信します。

## 3. クライアント配信単体
```bash
# ROS2ワークスペース経由
ros2 run joy_node_web client_server --ws-port 8700

# ROS2環境が無くても起動可能（fastapi + uvicorn のみ）
python3 -m joy_node_web.client_server --ws-url ws://192.168.10.135:8700/joys
```

| オプション | 既定値 | 説明 |
|---|---|---|
| `--host` | `0.0.0.0` | バインドアドレス |
| `--port` | `8701` | クライアントを配信するポート（ノードと同居できるよう8700とは別） |
| `--ws-url` | なし | ノードの`/joys`のURLを固定する（`--ws-port`より優先） |
| `--ws-port` | `8700` | ページを配信したホストの、ノード側ポート |

## クライアントのWebSocket接続先の決定順

1. `?ws=` クエリパラメータ（例: `http://host:8701/joy?ws=ws://192.168.10.135:8700/joys`）
2. 配信サーバが注入した設定（`--ws-url` / `--ws-port`）
3. ページを開いたホスト（ポート未指定ならページと同一オリジン）

画面上のURL欄で手動変更もできます。前回の接続先はブラウザに保存しません（別ロボットのページを開いたときに、以前のロボットへ黙って繋ぎに行くのを避けるため）。

クライアント本体は [joy_node_web/static/client.html](joy_node_web/static/client.html) の静的ファイルです。
nginx等の任意の静的サーバから配信することもできますが、その場合は設定が注入されないため`?ws=`で接続先を指定してください。
コントローラのWebクライアントはCORSに違反しない範囲で自由に作成できます。

# キーマップ

クライアント画面はひとつのカードに「接続」「コントローラ」「現在値」がまとまり、キーマップ操作はカード右下にあります。

| ボタン | 動作 |
|---|---|
| 設定変更 | キーマップ設定のモーダルを開く |
| インポート | JSONファイルの選択ダイアログを開いて読み込む |
| リセット | 割り当てを解除して生データ送信に戻す（保存内容も削除） |

「設定変更」のモーダル内でできること:

- 「割当開始」: 全スロットを先頭から順に設定。点滅しているスロットに対応する入力を操作するとバインドされ、次のスロットが点滅します（「スキップ」で飛ばす、「中断」で終了）
- 個別設定: スロットをクリックしてから割り当てたい入力を操作。Shift+クリックでそのスロットをクリア、`±` で軸・方向割り当ての符号を反転
- 「クリア」で全スロット解除、「エクスポート」でJSONファイルとして保存

## コントローラの選択と自動適用

- 「コントローラ」に Gamepad API が検出した全コントローラがボタンで並び、押すと使用するコントローラを切り替えられます（選択中のものが強調表示）
- キーマップは**コントローラ名とセットでブラウザに保存**され、同名のコントローラが接続・選択された時点で自動適用されます（複数のコントローラをそれぞれ別のキーマップで使えます）
- 保存済みキーマップが無いコントローラを選ぶと生データ送信になります

## 現在値の表示

「現在値」には、実際に `/joy` として送信している値をカンマ区切りで表示します（キーマップ適用後の値なので、未割り当てのスロットは 0 になります）。

```
Axes: 0.423, -0.200, 0.000, 0.000
Buttons: 0, 1, 0, 0, 0, 1
```

キーマップファイルのフォーマットと解釈は [g2e (ESP-NOW Gamepad Bridge)](https://g2e.s-phere.dev) と共通で、相互に読み込めます。詳細は [docs/COMMUNICATION_SPEC.md](docs/COMMUNICATION_SPEC.md#4-キーマップ仕様g2e-互換) を参照してください。
